# Phase 2A fixture tile layouts

This is the construction sheet for the Phase 2A scene saves declared in `fixtures/renderer-oracle/catalog.json`. Use it with the capture procedure in `phase2a-slim-plan.md` (item 5).

Since the slim plan was approved (2026-11-01), only the official package is captured, in one VM. Statements below about transferring saves to a reconstructed VM no longer apply; the save's SHA-256 is still its identity. §4 now produces only `season-summer-v1` and `season-winter-v1`; spring and autumn are not saved. §2's interaction layer is used only for the valid Condo preview; the clipped preview and road/rail overlays are no longer captured. §3 is captured as one fixed viewport.

## Coordinate and fidelity rules

- Every diagram is a logical top-down map, not a camera image. North is at the top, east is to the right, `x` increases east, and `y` increases south.
- Tile coordinates run from `(00,00)` through `(29,29)`. The two header rows show the `x` tens and ones; the left column is `y`.
- Object coordinates name the first tile clicked by the controller. If a contribution has a footprint, the diagram marks the intended occupied tiles.
- Terrain instructions name **grid vertices**, which run from `(00,00)` through `(30,30)`. A vertex is the shared diamond corner of adjacent tiles. In the checked controller, vertex `(x,y)` affects the matching corners of tiles `(x,y-1)`, `(x+1,y-1)`, `(x,y)`, and `(x+1,y)` when those tiles are in bounds; it does not edit one whole tile.
- For a terrain pass, click every listed vertex exactly once, then repeat the whole set for the next pass. Do not apply all repeated clicks to one vertex before moving to the next.
- If a terrain click is rejected, an object snaps somewhere else, or a named contribution is unavailable, stop and record it. Restart from a new empty map rather than improvising a nominally equivalent layout.
- These plans make the manually authored official save reproducible. The save's SHA-256 becomes the final identity. The reconstructed VM loads those exact bytes; it does not rebuild the diagrams independently.
- Keep the two-tile outer border empty unless a diagram explicitly uses it. Pause, force day, disable labels, and use height cut `None` while constructing.

### Locating a logical tile in the fixed quarter view

The ASCII rows do not correspond to horizontal screen rows. At equal `z`, the checked projection maps one `+x`/east tile step to `(+16,-8)` screen pixels and one `+y`/south step to `(+16,+8)` pixels. Each ground diamond is therefore 32 by 16 pixels at an unscaled 1:1 console.

After measuring the full-screen pixel center `Cref=(cx,cy)` of any known flat reference tile `(xr,yr)` for the current scroll position, the center of another flat tile is:

```text
dx = x-xr
dy = y-yr
center(x,y) = (cx + 16*(dx+dy), cy + 8*(-dx+dy))
```

Use the ground-diamond center as the controller pointer hotspot for every diagrammed tile anchor. Record the resulting full-screen coordinate in metadata. A different scroll position—including the clipped-preview and split-direction views—requires a newly measured `Cref`. Elevation shifts the rendered tile vertically, so measure directly when an endpoint is not on the common flat ground.

## Completion check before transferring saves

For every official-VM save:

1. Reload it once in the official package and confirm the diagrammed objects and terrain remain present.
2. Close controllers, pause, set the declared day/night and cut state, and record the neutral viewport/scroll position.
3. Shut down or revert before copying the save to host staging.
4. Compute the save SHA-256. From this point the save is immutable.
5. Transfer those exact bytes to the reconstructed VM; never use the diagrams to make a second “equivalent” world.
